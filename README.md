# CodeCraftHub

CodeCraftHub is a simple personalized learning platform built with Java and Spring Boot. It allows developers to track courses they want to learn and monitor their progress.

Course data is stored in a local `courses.json` file. No database, authentication, or user management is required.

## Features

- Create courses
- View all courses
- View a specific course by ID
- Update existing courses
- Delete courses
- Automatically generate course IDs
- Automatically record course creation timestamps
- Validate required fields
- Validate course status values
- Validate target dates using `YYYY-MM-DD`
- Automatically create `courses.json` if it does not exist
- Return helpful error responses for invalid requests, missing courses, and file errors

## Technology Stack

- Java 17+
- Spring Boot 3
- Spring Web
- Jackson JSON processor
- Bean Validation
- Maven
- Local JSON file storage

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/katerynaivanchuk/codecraft-hub.git
cd codecraft-hub
```

### 2. Confirm the project files

The project should contain at least:

- `pom.xml`
- `src/`

The `courses.json` file does not need to exist initially. The application creates it automatically when it starts.

If you want to create it manually, add the following file in the project root:

```json
[]
```

### 3. Install dependencies

Run:

```bash
mvn clean install
```

This downloads the required dependencies, compiles the application, and runs the tests.

## Running the Application

### Option 1: Run with Maven

From the project root, run:

```bash
mvn spring-boot:run
```

The application starts on:

```text
http://localhost:8080
```

The API base URL is:

```text
http://localhost:8080/api/courses
```

### Option 2: Run the packaged JAR

First, create the application JAR:

```bash
mvn clean package
```

Then run it:

```bash
java -jar target/codecraft-hub-0.0.1-SNAPSHOT.jar
```

> The exact JAR filename may differ depending on the version in `pom.xml`.

### Stop the application

Press `Ctrl+C`.

The course data remains in `courses.json` after the application stops.

## Data Storage

Course data is stored in `courses.json`. The file is located in the application's working directory, usually the project root.

Example:

```json
[
  {
    "id": 1,
    "name": "Spring Boot REST APIs",
    "description": "Learn how to build REST APIs with Spring Boot.",
    "target_date": "2026-12-31",
    "status": "Not Started",
    "created_at": "2026-11-15T12:30:45.123Z"
  }
]
```

The following fields are generated by the server:

- `id`
- `created_at`

The following fields must be provided when creating or updating a course:

- `name`
- `description`
- `target_date`
- `status`

## Course Fields

| Field         | JSON Type | Required | Description                                                      |
|---------------|-----------|----------|------------------------------------------------------------------|
| `id`          | Number    | No       | Automatically generated, starting from `1`                       |
| `name`        | String    | Yes      | Course name                                                      |
| `description` | String    | Yes      | Course description                                               |
| `target_date` | String    | Yes      | Target completion date in `YYYY-MM-DD` format                    |
| `status`      | String    | Yes      | Must be `Not Started`, `In Progress`, or `Completed`             |
| `created_at`  | String    | No       | Automatically generated timestamp                                |

## API Documentation

All endpoints use the following base URL:

```text
http://localhost:8080/api/courses
```

Requests containing JSON should use this header:

```text
Content-Type: application/json
```

### Create a Course

Creates a new course.

**Request**

```http
POST /api/courses
Content-Type: application/json
```

**Example using cURL**

```bash
curl -X POST http://localhost:8080/api/courses \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Spring Boot REST APIs",
    "description": "Learn how to build REST APIs with Spring Boot.",
    "target_date": "2026-12-31",
    "status": "Not Started"
  }'
```

**Example response**

```http
HTTP/1.1 201 Created
```

```json
{
  "id": 1,
  "name": "Spring Boot REST APIs",
  "description": "Learn how to build REST APIs with Spring Boot.",
  "target_date": "2026-12-31",
  "status": "Not Started",
  "created_at": "2026-11-15T12:30:45.123Z"
}
```

**Notes**

Do not provide `id` or `created_at` in the request. These values are generated by the server.

### Get All Courses

Returns all courses stored in `courses.json`.

**Request**

```http
GET /api/courses
```

**Example using cURL**

```bash
curl http://localhost:8080/api/courses
```

**Example response**

```json
[
  {
    "id": 1,
    "name": "Spring Boot REST APIs",
    "description": "Learn how to build REST APIs with Spring Boot.",
    "target_date": "2026-12-31",
    "status": "Not Started",
    "created_at": "2026-11-15T12:30:45.123Z"
  },
  {
    "id": 2,
    "name": "Java Collections",
    "description": "Learn lists, sets, and maps in Java.",
    "target_date": "2027-01-15",
    "status": "In Progress",
    "created_at": "2026-11-15T12:35:10.456Z"
  }
]
```

If there are no courses, the response is:

```json
[]
```

### Get a Specific Course

Returns one course by ID.

**Request**

```http
GET /api/courses/{id}
```

**Example**

```bash
curl http://localhost:8080/api/courses/1
```

**Example response**

```json
{
  "id": 1,
  "name": "Spring Boot REST APIs",
  "description": "Learn how to build REST APIs with Spring Boot.",
  "target_date": "2026-12-31",
  "status": "Not Started",
  "created_at": "2026-11-15T12:30:45.123Z"
}
```

**Course not found response**

If the course ID does not exist:

```http
HTTP/1.1 404 Not Found
```

```json
{
  "timestamp": "2026-11-15T12:40:00.000Z",
  "status": 404,
  "error": "Course not found",
  "message": "Course with id 99 was not found"
}
```

### Update a Course

Replaces an existing course.

**Request**

```http
PUT /api/courses/{id}
Content-Type: application/json
```

**Example using cURL**

```bash
curl -X PUT http://localhost:8080/api/courses/1 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Advanced Spring Boot REST APIs",
    "description": "Build more advanced REST APIs with Spring Boot.",
    "target_date": "2027-01-31",
    "status": "In Progress"
  }'
```

**Example response**

```json
{
  "id": 1,
  "name": "Advanced Spring Boot REST APIs",
  "description": "Build more advanced REST APIs with Spring Boot.",
  "target_date": "2027-01-31",
  "status": "In Progress",
  "created_at": "2026-11-15T12:30:45.123Z"
}
```

The original `id` and `created_at` values are preserved by the server.

### Delete a Course

Deletes a course by ID.

**Request**

```http
DELETE /api/courses/{id}
```

**Example using cURL**

```bash
curl -X DELETE http://localhost:8080/api/courses/1
```

**Successful response**

```http
HTTP/1.1 204 No Content
```

A successful delete does not return a response body.

**Course not found response**

If the course ID does not exist, the API returns:

```http
HTTP/1.1 404 Not Found
```

## Validation Rules

### Required fields

The following fields cannot be missing or blank:

- `name`
- `description`
- `target_date`
- `status`

### Valid statuses

The status must exactly match one of these values:

- `Not Started`
- `In Progress`
- `Completed`

These values are case-sensitive.

The following examples are invalid:

- `not started`
- `IN_PROGRESS`
- `Complete`
- `Started`

### Date format

The `target_date` field must use `YYYY-MM-DD`.

Valid example:

```json
{
  "target_date": "2026-12-31"
}
```

Invalid examples:

- `12/31/2026`
- `31-12-2026`
- `2026/12/31`

## Error Responses

### Missing or invalid fields

Example request:

```json
{
  "name": "",
  "description": "",
  "target_date": "31-12-2026",
  "status": "Started"
}
```

Possible response:

```json
{
  "timestamp": "2026-11-15T12:45:00.000Z",
  "status": 400,
  "error": "Validation failed",
  "fields": {
    "name": "name is required",
    "description": "description is required",
    "status": "status must be exactly one of: Not Started, In Progress, Completed"
  }
}
```

### Invalid JSON or date format

```json
{
  "timestamp": "2026-11-15T12:46:00.000Z",
  "status": 400,
  "error": "Invalid JSON request",
  "message": "Check the JSON syntax, date format, and field value types"
}
```

### File errors

If the application cannot read or write `courses.json`, it returns:

```json
{
  "timestamp": "2026-11-15T12:47:00.000Z",
  "status": 500,
  "error": "Course file error",
  "message": "Unable to read courses from ..."
}
```

## Troubleshooting

### 1. `java: command not found`

Java is not installed or is not available on your system `PATH`.

Check Java:

```bash
java -version
```

Install JDK 17 or newer and configure `JAVA_HOME`.

Example on Linux or macOS:

```bash
export JAVA_HOME=/path/to/jdk-17
export PATH="$JAVA_HOME/bin:$PATH"
```

### 2. `mvn: command not found`

Maven is not installed or is not available on your system `PATH`.

Check Maven:

```bash
mvn -version
```

Install Maven and configure its executable directory on your `PATH`.

### 3. Port 8080 is already in use

Another application is using port `8080`.

You can either stop the other application or change the port in `src/main/resources/application.properties`.

For example:

```properties
server.port=8081
```

The API will then be available at:

```text
http://localhost:8081/api/courses
```

### 4. `courses.json` is not created

The file is created relative to the application's current working directory.

Make sure you start the application from the project root:

```bash
cd codecraft-hub
mvn spring-boot:run
```

The file should appear as `codecraft-hub/courses.json`.

### 5. Invalid JSON in `courses.json`

Make sure the file contains valid JSON. An empty course list should be represented as:

```json
[]
```

Do not leave the file completely empty or add comments inside the JSON file.

You can replace its contents with `[]` and then restart the application.

### 6. Course data is not being saved

Check the following:

- The application has permission to write to the project directory.
- `courses.json` is not read-only.
- Another application is not locking the file.
- The application console does not report a file write error.
- You are checking the correct `courses.json` file.

### 7. A request returns `400 Bad Request`

Check the following:

- The request body is valid JSON.
- The `Content-Type` header is `application/json`.
- All required fields are present.
- `target_date` uses `YYYY-MM-DD`.
- `status` exactly matches one of the allowed values.
- No fields contain invalid data types.

Example of a valid request:

```json
{
  "name": "Java Fundamentals",
  "description": "Learn the fundamentals of Java programming.",
  "target_date": "2026-12-31",
  "status": "Not Started"
}
```

### 8. A request returns `404 Not Found`

Check that:

- The application is running.
- The URL is correct.
- The course ID exists.
- The endpoint includes the `/api/courses` path.

For example:

```text
GET http://localhost:8080/api/courses/1
```

### 9. Changes to Java code are not visible

Stop and restart the application with `Ctrl+C`, then run:

```bash
mvn spring-boot:run
```

Or rebuild the project:

```bash
mvn clean package
```

## Limitations

This project intentionally uses a JSON file instead of a database. It is suitable for learning REST APIs and small local applications.

A JSON file is not ideal for:

- Many simultaneous users
- Multiple application instances
- Large amounts of course data
- Complex searching or filtering
- Advanced transaction handling
- Production-scale deployments

A database such as PostgreSQL, MySQL, or H2 would be more appropriate for a larger application.
